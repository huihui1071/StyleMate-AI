# StyleMate Supply

StyleMate Supply 是一个面向服装零售商家、买手与采购人员的供应商智能选款台。商家用自然语言描述渠道、客群、品类、零售价带和采购预算，系统从匿名货盘中执行硬筛选，完成组货结构和建议件数，并形成可以调整的采购清单。

它不是面向消费者的穿搭聊天机器人，也不是让模型凭感觉挑几张商品图。商品是否进入候选由结构化条件决定；主销、引流、形象、连带和测试款由可检查的组货规则分配；锁货、议价、账期、合同和真实下单由销售人员接管。

## 完整业务流程

```text
商家画像
  → 选款硬筛选
  → 五类角色组货
  → 可调整采购清单
  → 销售接管
```

### 1. 商家画像

演示商家包含经营渠道、目标客群、零售价带、风格偏好、默认预算、商家等级、折扣系数和样衣额度。切换商家会清空结果与采购清单，避免画像和价格规则串用。

### 2. 智能选款

系统识别并执行人群、渠道、品类、季节、颜色、版型、材质、匿名系列、零售价带和 MOQ 等条件。没有完全命中时明确返回空结果，不会自动放宽硬条件。

### 3. 结构化组货

组货不是若干高分商品的简单拼接。系统先形成候选范围，再分配五种经营角色：

- 主销款：承担主要销量，优先供货稳定与毛利空间。
- 引流款：覆盖价格带下沿，降低首次购买门槛。
- 形象款：强化店铺风格与视觉表达。
- 连带款：补足易组合销售的品类。
- 测试款：用较低件数验证新风格与库存风险。

### 4. 采购清单

建议商品会进入采购侧栏。数量以 MOQ 为最小单位调整，并实时更新款数、件数、采购金额、预计零售额和毛利空间。

### 5. 销售接管

涉及实时库存、锁货、议价、账期、合同、发票、物流或售后时，AI 只生成包含商家与需求上下文的接管摘要，不执行真实交易，也不作价格或库存承诺。

## 演示货盘

- 240 条匿名 SKU，覆盖 4 个匿名系列和 22 个品类。
- 240 张来自项目资料并已本地化处理的真实商品图片。
- 商品属性包含品类、颜色、版型、材质、季节、风格和工艺。
- 供货价、建议零售价、库存、MOQ、交期、渠道、折扣和经营测算为演示模拟字段。
- 仓库不保留真实企业名、真实品牌名、源款号、源 SKC、原始图片链接或源文件元数据。

## 可以直接体验的任务

```text
我在淘宝做女性通勤装，零售价 300–700 元，想选 12 款春季新品，首批采购预算 3 万
帮我选女装春季上装，零售价 300–700 元，起订量不超过 4 件
查看当前商家的拿货政策、折扣和样衣额度
请联系销售确认这份选款单并锁库存
```

## 系统结构

```text
React 产品官网与选款工作台
        ↓ 同域 API
FastAPI 请求解析与决策服务
        ↓
匿名商品货盘 + 商家画像 + 确定性业务规则
```

生产部署使用单个 Docker 服务。Vite 构建产物、商品图片和 FastAPI API 由同一域名提供，避免前端上线后仍依赖本地接口。

## 本地运行

### 后端

```bash
cd StyleMate-AI
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m uvicorn apps.api.main:app --reload --port 8000
```

### 前端

另开一个终端：

```bash
cd StyleMate-AI
npm install
npm run dev:web
```

访问 `http://localhost:5173` 查看产品官网，进入 `http://localhost:5173/demo` 使用选款工作台。

也可以使用 Docker：

```bash
docker compose up --build
```

## 验证

```bash
npm run check
```

完整检查包含隐私扫描、后端规则测试、前端工具测试和生产构建。后端测试覆盖 200+ 图片货盘、复合条件解析、硬筛选、组货角色、预算控制、MOQ、商家差异和销售接管。

## 在线部署

仓库根目录提供单服务 `Dockerfile` 与 `render.yaml`，可作为 Render Blueprint 部署。健康检查地址为 `/api/health`。免费实例在长时间没有访问后可能休眠，首次打开需要等待服务唤醒。
